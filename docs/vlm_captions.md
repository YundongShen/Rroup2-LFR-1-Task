# VLM pseudo-captions for split A: a negative result

**Question.** Split A has images but no captions. Can a local vision-language model (VLM) write captions for those images, so that CLIP can be fine-tuned contrastively on A as if it were labelled?

**Answer so far: no, not with plain captioning.**
- Gemma 4 12B captions are fluent, and zero-shot CLIP finds them *more* image-specific than RSICD's human captions.
- As training targets they are worth about a quarter of a human caption.
- Adding them for A on top of B's human captions makes results *worse* in all 5 folds, and the drop grows with the weight on the A term.

Code: `src/methods/capft.py`, `configs/method/capft.yaml`, `configs/train/pilot.yaml`, `scripts/vlm/`.
Captions: `data/vlm_captions/{A,B}_v2_n1.jsonl`.

## Data usage
- **Split A:** images only. The captions of A in `dataset_rsicd.json` are never read; the captioning script only reads B captions, used as style examples. Image **filenames are never sent to the VLM**, because they contain the class name (`airport_1.jpg`).
- **Split B:** image–caption pairs, using the framework's stratified 5-fold split (`data=kfold5`): train on 4 folds, evaluate on the 5th. As in the rest of the framework, the B class labels are used only for stratifying the folds and for zero-shot evaluation on the held-out fold.
- **Split C:** not used. No run in this document touches C.
- All processing is automated: the captions are generated by a script and never edited by hand.

## Captioning setup
- **Model and hardware:** `gemma4:12b-mlx` served by Ollama 0.40.5 on an Apple M4 Max (36 GB), with thinking off, temperature 0.7 and one caption per image.
- **Prompt (`v2`):** asks the model to first decide the overall scene or most prominent structure, then write a short caption that names it. Three fixed B captions are given as style examples. **No class list is given.**
- **Throughput:** 0.77 s per image with 4 parallel requests, 1.2–1.5 s per image sequentially.
  - Ollama's MLX engine does not batch the generation step. Parallel requests only overlap image encoding with generation, so throughput stops improving at 4 requests.
  - Five captions in one request take about 3 s per image, and the five are mostly near-duplicates.
- **Coverage:**
  - all 1,094 B images;
  - **1,808 of 8,734 A images** (21%), a seeded random subset. The run was stopped there once the pilot below showed that more A captions would not help.

## Caption analysis (split B)
- **Overlap with the human captions:**
  - Content-word precision 0.34, recall 0.23, F1 0.25, against the union of each image's 5 references.
  - Captions average 8.7 words, and 885 of the 1,094 are unique.
- **Strengths:** in hand-checked samples, colours, roofs, pools, boats and courts are described correctly and counts are usually right (e.g. "three large cylindrical storage tanks"). There are few outright hallucinations.
- **Failure modes:**
  - **"Stadium" bias.** 133 of 1,094 captions (12%) start with "the stadium is…", absorbing playgrounds, tennis and basketball courts and baseball fields. This is the same kind of class bias zero-shot CLIP shows on RSICD (see `docs/a_only_rose.md` on the `yundong/a-only` branch).
  - **Small objects are missed.** At 224 px, planes are often not seen, so airports become "industrial facility" or "port".
  - **The main structure is misread.** For example, a wide road bridge over a river is captioned as "a large stadium near a river".
- **Retrieval check** (zero-shot ViT-B/32, one query caption per B image, a gallery of 1,094 images):

| Query caption | i2t R@1 | i2t R@5 | t2i R@1 | t2i R@5 |
|---|---|---|---|---|
| Human, caption 0 | 3.4 | 13.3 | 3.7 | 14.5 |
| Human, random of 5 | 3.7 | 16.7 | 4.3 | 15.8 |
| Gemma v2 | 7.9 | 25.7 | 8.3 | 25.6 |

This turned out to be **misleading**. Gemma writes in web-caption language that CLIP already handles well, and many RSICD human captions are generic or repeated across images. High retrievability under zero-shot CLIP did **not** predict that the captions would be useful for training (see below).

## Results
**Setup for every row:**
- Model: OpenCLIP ViT-B/32 `laion2b_s34b_b79k`, fully fine-tuned (both towers).
- Loss: symmetric InfoNCE with CLIP's learned temperature.
- Training: 10 epochs, batch 64, AdamW (lr 1e-5, wd 0.1), 20 warmup steps then cosine decay.
- No checkpoint selection: the held-out fold is used only for evaluation, always against **human** captions.
- Numbers are the mean ± std over the 5 B folds, one seed per fold.
- In the A runs, each step adds one A batch of 64 (image, Gemma caption) pairs with its own InfoNCE term: L = L_con(B) + λ·L_con(A).

| B-train, Gemma caption (1/img) | 64.3 ± 2.1 | 64.6 ± 2.2 | 16.4 ± 1.8 | 16.7 ± 1.8 | 39.6 ± 2.7 | 51.2 ± 2.1 | 41.5 ± 1.3 |

## Interpretation
1. **A Gemma caption is a much weaker training target than a human one.**
   - With the same images and the same number of captions, Gemma gives +0.7 acc and +4.6 mR over zero-shot.
   - A human caption gives +17.1 acc and +19.4 mR.
   - Our explanation: the human RSICD captions almost always name the scene ("…in an airport", "…near a viaduct"), and that matches both the zero-shot prompts and the test captions. Gemma's captions often leave the scene out or get it wrong (the stadium bias, missed planes).
2. **Adding A with Gemma captions hurts, and the damage scales with λ.** With λ = 1 the drop shows up in every fold, for both accuracy and mR. Our reading is that the captions themselves push the model the wrong way. More of A would not fix this, because the problem is caption quality, not coverage.
3. **Fully fine-tuning on B alone is a strong baseline:** 84.0% zs acc and 58.1 mR on held-out B. Any semi-supervised method should be compared against it. (The README's "Supervised" row is on C and uses an adapter only, so it is not directly comparable.)

## Limitations
- One seed per fold, and a fixed training recipe with no tuning of epochs or learning rate. Training loss reaches about 0.2 by epoch 10, so the B-only model may be overfitting.
- Only 21% of A was captioned. Only one VLM (12B) and one prompt were tried for training.
- Evaluation is on held-out B folds, not C.

## Possible next steps
- **Class-aware captioning:** give the VLM the 31 class names so that each caption names the scene. This effectively turns the VLM into a zero-shot labeller and must be reported as such. Stop rule: continue only if the "B-train, Gemma caption" row moves clearly toward the 1-human-caption row.
- **Confidence weighting or filtering** of A captions, e.g. by a CLIP score from a model fine-tuned on B, or by class balancing in the style of ROSE's Sinkhorn step.
- **Distillation from a CLIP teacher fine-tuned on B,** using soft rankings over the real B captions instead of generated text.

## Reproduce
```bash
# captions (Ollama running; add OLLAMA_NUM_PARALLEL=4 to the server for --parallel 4); resumable
python scripts/vlm/caption_ollama.py --data data/raw --split val   --prompt v2 --n 1 --parallel 4 --out data/vlm_captions/B_v2_n1.jsonl
python scripts/vlm/caption_ollama.py --data data/raw --split train --prompt v2 --n 1 --parallel 4 --out data/vlm_captions/A_v2_n1.jsonl
python scripts/vlm/caption_overlap.py data/raw/dataset_rsicd.json data/vlm_captions/B_v2_n1.jsonl
python scripts/vlm/caption_retrieval.py --captions data/vlm_captions/B_v2_n1.jsonl

# pilot (B only) and B + A
python -m src.run model=vit_b32_laion2b data=kfold5 exp_name=pilot_zeroshot
python -m src.run method=capft train=pilot model=vit_b32_laion2b data=kfold5 method.b_source=vlm   exp_name=pilot_b_vlm
python -m src.run method=capft train=pilot model=vit_b32_laion2b data=kfold5 method.b_source=real1 exp_name=pilot_b_real1
python -m src.run method=capft train=pilot model=vit_b32_laion2b data=kfold5 method.b_source=real  exp_name=pilot_b_real
python -m src.run method=capft train=pilot model=vit_b32_laion2b data=kfold5 method.b_source=real method.a_source=vlm method.a_weight=1.0 exp_name=b_real_a_vlm_w1.0
python -m src.run method=capft train=pilot model=vit_b32_laion2b data=kfold5 method.b_source=real method.a_source=vlm method.a_weight=0.5 exp_name=b_real_a_vlm_w0.5
python scripts/vlm/summarize.py
```
Training and evaluation used `device=mps` (Apple GPU). Each 5-fold run takes about 14 min for B only and about 30 min with A.

*AI tools:* Claude Code was used to write the captioning, analysis and training scripts, to run the experiments and to draft this document. All results come from the logged runs in `runs/`.
